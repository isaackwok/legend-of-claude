## 1. 這是什麼、為什麼要做

克勞德傳說是一款**跑在自己電腦上的單人 RPG**。表面上是一座可以走動、和 NPC 互動的手繪風城鎮；底下其實是一套 **Claude agent 的管理工具**：

| 遊戲裡 | 實際上 |
|---|---|
| NPC（冒險者） | 一個 Agent SDK agent，有自己的人設、模型、技能與可用的 connectors |
| 技能 | Claude Skills（一個資料夾＋`SKILL.md`） |
| 裝備 | 這個 NPC 可以使用的 claude.ai connectors，以及工具限制 |
| 委託 | 一項真實的工作（例如 Jira 票、調查 bug、解釋程式流程） |
| 地下城 | 一個登記過的本機專案資料夾 |
| 冒險 | NPC 在某個專案裡執行委託的那一次 agent session |
| 卷軸 | NPC 帶回來的報告 |

**為什麼做【決定】**：讓工作用「玩遊戲」的方式進行，而且要**產生真實價值**——Jira 票真的被處理、bug 真的被修好。兩者都要成立才算成功。

**長期方向【決定】**：越來越自動化，例如匯入整個 Sprint 的票，讓 NPC 自動規劃與執行。v1 不做，但資料模型要預留（見 §6）。

**玩家的角色【決定】**：玩家是「公會會長」——走動、派委託、驗收、結算。玩家角色**不做事、不裝技能**；所有工作都委派給 NPC。

## 2. 目標、非目標、反目標

**目標**
- 用遊戲方式完成真實的軟體工作：處理 Jira 票、調查並修正 bug、解釋某段程式的流程與邏輯【決定】。
- 遊戲體驗優先：介面與名詞盡量用遊戲的說法，除非會大幅影響閱讀或理解【決定】。
- 在遊戲和 Claude Code 之間切換時行為一致（權限模式、session 續聊）【決定】。

**非目標（v1 不做）**
- 多人連線、發佈給別人玩【決定】。
- 隊伍、經驗值與成就、魔力泉、新手教學任務、從 GitHub/zip 匯入技能（排在 v2）【決定】。
- Sprint 整批匯入與自動規劃、隊員互相討論、Electron 打包、系統通知（更之後）【決定】。
- 依專案資料夾結構畫地下城地圖【決定：使用者明確拒絕】。

**反目標（就算功能都動了，出現這些也算失敗）**
- 遊戲數值擋住真實工作（例如「金幣不夠不能派委託」）【建議・未否決】。
- 動畫為了演出而落後真實進度、誤導玩家以為 NPC 還在做某件事【建議・未否決】。
- 需要跑去本機 Claude Code 改設定才能讓遊戲運作【決定】。
- 畫面中出現 emoji 或風格不一的素材【決定】。

## 3. 限制

- **登入與計費【決定】**：用 claude.ai 帳號登入，NPC 的回覆與工作都算在使用者的訂閱方案用量（Agent SDK 目前的規則）。這只適用於使用者本人在本機使用；Anthropic 不允許第三方產品讓其他使用者用 claude.ai 登入。
  - 若環境變數有 `ANTHROPIC_API_KEY`（或 `ANTHROPIC_AUTH_TOKEN`、`apiKeyHelper`），SDK 會改用 API 計費，而且 **claude.ai connectors 不會被載入**。【規劃時的決定，可推翻】遊戲啟動 NPC 時直接從子程序環境中**移除** `ANTHROPIC_API_KEY` 與 `ANTHROPIC_AUTH_TOKEN`，並在畫面上提示「已忽略」，確保一定走訂閱與 connectors。
  - 使用者需先在這台電腦用 claude.ai 帳號登入過一次 Claude Code（SDK 讀取該憑證）。
- **Connectors 來源【決定】**：Atlassian、GitHub 等 connectors 已在 claude.ai 設定好，遊戲直接使用；增刪改都在 claude.ai 網頁上做。
  - 官方文件確認：用 claude.ai 登入時，Agent SDK session 會從 claude.ai 取得 connectors。
- **與本機 Claude Code 解耦【決定】**：遊戲不依賴**使用者層級** `~/.claude` 裡的設定、技能、MCP。NPC、技能、權限在遊戲裡管理。（作法見 §5.2【待驗證】）
- **專案自己的 Claude 設定：全部讀取【決定】**：NPC 在某座地下城工作時，載入該專案的 `CLAUDE.md`、`.claude/settings.json`（含 hooks、權限規則）、`.claude/skills`、`.mcp.json`，行為盡量等同使用者在那個專案裡用 Claude Code。也就是 `settingSources` 包含 `project`（是否含 `local`【建造者自定】），但不含 `user`。
  - 影響：NPC 除了遊戲裡裝的技能外，還會帶著「地下城自帶」的技能與工具。背包與點擊查看時要把這些另外標示為「地下城自帶」，玩家才知道 NPC 實際有哪些能力。
  - 專案設定中的權限規則與 hooks 照樣生效，可能讓某些動作多出批准請求或被擋下，這是預期行為。
- **單機、本機網頁【決定】**：v1 是本機網頁版（見 §4）。
- **美術【決定】**：沒有現成素材；**所有素材自製 SVG，不使用 emoji**。風格參考 Greedy Cave（手繪墨線、羊皮紙）。

## 4. 技術選擇【決定】

使用者熟悉 React/TypeScript，用過 Phaser 做橫向捲軸遊戲。

- **形式**：本機網頁版。一個指令啟動，在瀏覽器裡玩。前後端切乾淨，以便日後包成 Electron。
- **Repo 結構**：
  - `client/`：Vite + React + Phaser
  - `server/`：Node + `@anthropic-ai/claude-agent-sdk`（TypeScript）
  - `shared/`：前後端共用型別（委託、NPC、技能、地下城、事件）
- **畫面分工**：Phaser 負責遊戲世界（城鎮、角色移動、NPC、地下城場景）；所有介面（佈告欄、對話、招募表單、背包、水晶球）用 React 疊在 Phaser 畫面之上。
- **狀態管理**：Zustand。Phaser 端用 `getState / setState / subscribe`，React 端用 hook，共用同一個 store。**每一格都在變的資料（座標、動畫影格）不放 store，由 Phaser 自己管**；store 只放遊戲事實（NPC、委託狀態、誰在冒險、開著哪個介面、串流進來的訊息）。
- **前後端溝通**：一般 CRUD 用 HTTP；NPC 串流回覆、冒險事件、批准請求用 WebSocket。
- **安全性（v1 第一天就要做）**：伺服器只綁 `127.0.0.1`；啟動時產生隨機 token，網址必須帶 token 才能連線（HTTP 與 WebSocket 都要驗）；檢查 `Origin`。理由：本機伺服器能讓 NPC 執行指令與改檔，其他網站不能有機會觸發。
- **存檔**：獨立的遊戲資料夾（跟專案原始碼分開），NPC、委託等各存成 JSON，方便人工查看與修改。技能用 Skills 格式（資料夾＋`SKILL.md`）。實際位置【建造者自定】（例如 `~/.legend-of-claude/`）。

## 5. 核心機制

### 5.1 NPC

**欄位與 Agent SDK 對應【建議・未否決】**

| 招募表單 | 對應 |
|---|---|
| 名字／稱號、外觀 | 只存在遊戲裡 |
| 人設（個性＋專長） | `systemPrompt`，接在 Claude Code 預設 prompt 之後 |
| 資質（模型）／專注度 | `model`、`effort` |
| 裝備 | 允許使用哪些 claude.ai connectors；「唯讀之戒」＝`disallowedTools` 禁止 Edit/Write |
| 技能 | 這個 NPC 載入的 Skills |
| 駐地 | 預設的地下城（`cwd`），派委託時可改，可留空 |

- **權限模式固定為 `auto`【決定】**，與 Claude Code 的 Auto Mode 一致，不放在表單上。
- **職業＝預設模板【建議・未否決】**，選了會自動填大部分欄位：
  - 戰士：修 bug、實作。Opus、effort 高、可改檔。
  - 學者：讀程式、解釋流程、寫調查報告。Sonnet、戴唯讀之戒。
  - 斥候：快速查找。Haiku、effort 低、唯讀。
  - 自由人：空白模板。
  - （具體模型 ID 用當下最新的 Claude 模型【建造者自定】）
- **酒館老闆幫寫人設【建議・未否決】**：玩家只寫一句描述，由內建 NPC 擴寫成完整人設，玩家可再改。
- **招募流程**：第 0 步選職業 → 身分 → 資質 → 裝備 → 技能 → 駐地。
- **裝備／技能的選法【決定】**：不用一整排 pill。改用**背包式**：左邊只列「已裝上的」（短、好讀，按 ✕ 卸下）；右邊「公會倉庫」是格子背包，有分頁（全部／技能／裝備／常用）與搜尋框，點一下裝上或卸下，滑過顯示說明（名稱、用途、來源、幾位冒險者裝了它）。
- **技能數量不設上限【決定】**。
- **一個 NPC 同時只執行一個委託【我的決定，可推翻】**：場上只有一個本體，畫面規則簡單。冒險途中和他說話＝對該委託 session「傳信」，不另開閒聊。需要並行就多招募幾位（招募不受限制，所以這不算「遊戲規則擋住真實工作」）。Store 中「誰在冒險」為每個 NPC 一個值。

### 5.2 技能（法師塔）

技能存在遊戲資料夾內，格式為 Claude Skills。取得方式（v1）【建議・未否決】：

1. **抄寫典籍**：從 `~/.claude/skills` 挑選，**一次性複製**進遊戲（之後兩邊互不影響，維持解耦）。
2. **研究新技能**：一句話描述，由內建 NPC「大法師」寫出 `SKILL.md`。
3. **手抄修改**：在遊戲裡直接編輯 `SKILL.md`。

- 修改技能後，所有裝了它的 NPC 一起更新（共用同一份）。
- 從 GitHub 網址或 zip 匯入：v2。
- **【待驗證】** 每個 NPC 只載入「自己裝的」技能的具體作法（SDK 支援從指定路徑載入 plugins／skills，但「每個 NPC 各一套」要實驗）。
- **【待驗證】** 關閉本機設定來源（`settingSources`）後，claude.ai connectors 是否仍會載入。

### 5.3 裝備（connectors）

- 裝備清單來源【建議・未否決】：遊戲在背景啟動一個輕量 SDK session，從初始化訊息讀出使用者在 claude.ai 有哪些 connectors。玩家在 claude.ai 新增 connector 後，回遊戲按「盤點倉庫」更新清單。
- 工具限制（如唯讀之戒）是遊戲內建的裝備。
- 每個 NPC 能用的 connectors 可以不同。

### 5.4 內建 NPC【建議・未否決】

- **公會櫃檯**：負責所有 Jira 讀寫（匯入、改狀態、留言）。站在佈告欄旁，不可招募、不接一般委託。只帶 Atlassian 與 GitHub connectors 和 Jira 相關技能，用便宜快速的模型。
- **酒館老闆**：幫寫人設。
- **大法師**：幫研究新技能。
- **三位新手冒險者**：戰士、學者、斥候各一，讓玩家一開始就有人可派。

理由：遊戲伺服器本身**碰不到 claude.ai connectors**（只有 SDK session 裡能用），所以所有 Jira 操作都必須由某個 NPC 執行，也因此會消耗訂閱用量。

### 5.5 地下城（本機專案）

- 地下城＝**本機專案資料夾**，不是從 connector 來的【決定】。
- **地下城地圖（登記畫面）【建議・未否決】**：伺服器掃描指定資料夾（預設 `~/dev`），列出其中的 git 專案供勾選登記；也可手動貼路徑。登記時讀取 git remote，自動對應 GitHub repo（供開 PR 用）。
- 網頁版拿不到資料夾選擇器的完整路徑，所以由伺服器掃描。

### 5.6 委託與佈告欄

- **佈告欄＝遊戲內獨立的看板，與 Jira 分開管理【決定】**，用**分欄看板**呈現（使用者選 A）：待接委託／冒險中／待驗收／已完成。
- **委託來源**：
  - 玩家自己在佈告欄貼委託（例如「幫我看一下派單流程」）。
  - 輸入票號，由公會櫃檯從 Jira 匯入。
- **任務兩種【決定】**：真實任務（核心）；遊戲內任務（引導玩家互動與探索功能，v2 才做）。
- **難度星等【建議・未否決】**（v1 先存資料，v2 才拿來算經驗值）：Jira 匯入的依 story points 換算 ★1–★5，沒有則看優先度；自己貼的由公會櫃檯建議星等。玩家都可改。

### 5.7 執行委託（冒險）

- 派委託時選地下城（預設 NPC 的駐地）。
- **隔離【建議・未否決】**：每個委託在一個獨立的 git worktree＋分支中進行，多個 NPC 同時在同一專案工作不會互相干擾。分支命名、worktree 位置【建造者自定】。
- **權限**：`auto` mode【決定】。SDK 判斷需要批准時（例如分類模型拿不定主意、connector 被設為每次詢問），經 `canUseTool` 送到遊戲，呈現為**信鴿帶回求援信**：寫明 NPC 想做什麼、為什麼，玩家按同意或拒絕。玩家正在別處時信放進信箱，NPC 原地等待【建議・未否決】。
- **auto mode 不可用時的退路【我的決定，可推翻】**：官方文件已列出 SDK 支援 `permissionMode: 'auto'`，但可用性依方案／模型而定。若某 NPC 的模型不支援，改用 `acceptEdits`（工作目錄內改檔自動放行），其餘需要批准的 Bash／connector 呼叫走信鴿；並在 NPC 卡片上標示「謹慎模式」。不使用 `bypassPermissions`。
- 做完後 commit 到該分支，委託轉為「待驗收」，附上說明卷軸。**推上遠端與開 PR 在驗收時才做**【建議・未否決】。
- 調查類／解釋類委託，產出是報告卷軸（v1 存在委託與 session 中即可；「書庫」收藏卷軸【建造者自定】是否 v1 做）。

### 5.8 驗收與結算【決定】

玩家在佈告欄按「驗收通過」後，跳出結算視窗，勾選要執行的動作：

- 推上分支並開 PR
- 把 Jira 狀態改為 ___（下拉，列出該票目前可轉換的狀態）
- 在 Jira 留言，附上說明（由卷軸整理，送出前可編輯）
- 在 Jira 貼上 PR 連結（需先勾開 PR）
- 在瀏覽器打開這張 Jira 票

由公會櫃檯依序執行。遊戲記住上次勾選並自動帶入【建議・未否決】。非 Jira 委託只顯示適用的選項。

### 5.9 對話與記憶【決定】

- 行為和 Claude Code 一樣：**每段對話都是一個可續聊的 session**。
- 一個委託對應一個 session。跟 NPC 閒聊也是 session。
- 沒點開舊 session 而是開新對話時，NPC 不會記得舊內容，但可以翻閱自己帶回的卷軸【建議・未否決】。
- **Compact**：SDK 自動壓縮，遊戲顯示「正在整理筆記」。
- **Prompt cache**：只影響用量，不影響記憶。不需特別處理。
- **只在遊戲裡續聊【決定】**：遊戲的 session 不需要能在 Claude Code（CLI／Desktop）裡打開，Claude Code 的 session 也不出現在水晶球。遊戲的 session 存在遊戲自己的地方，由遊戲控制保存期限。
- **作法【規劃時確認】**：Agent SDK 提供 `sessionStore` 介面，遊戲實作一個存在遊戲資料夾的 `FileSessionStore`，續聊時從它讀回。注意 SDK 是「雙寫」：新 session 仍會在 `~/.claude/projects/` 留一份本機副本（會被 Claude Code 定期清掉，不影響遊戲），遊戲的那份才是正本。
- **閒聊不改檔【規劃時的決定，可推翻】**：跟 NPC 閒聊時一律唯讀，因為閒聊是在專案的主工作目錄進行，不是在委託的獨立分支上。要改東西請開委託。
- **保存期限（原待驗證，已由上面的作法處理）**：SDK 預設把紀錄寫在 Claude Code 的資料夾，並受其自動清理（預設天數待確認，約 30 天）影響。實作時選一種讓紀錄由遊戲掌控的作法（例如為遊戲指定獨立的設定資料夾，或由遊戲自己保存並在續聊時還原），前提是不影響 claude.ai 登入憑證的讀取。目標：冒險日誌不會無故少頁。

### 5.10 地下城觀戰

- **場景【決定＋建議】**：不依資料夾結構畫地圖【決定】。每座地下城是固定的手繪場景，內有工作站：書架、鐵砧、競技場、法陣區；可用專案名稱決定配色／擺設以示區別【建議・未否決】。
- **動作對照表【決定：使用者認可】**（由 SDK 串流的工具呼叫翻譯）：

| 實際動作 | 遊戲呈現 |
|---|---|
| Read / Grep / Glob | 在書架前翻閱古籍 |
| Edit / Write | 在鐵砧前鍛造 |
| 跑測試（Bash） | 在競技場和怪物戰鬥；失敗＝怪物還活著，全過＝擊敗 |
| 其他 Bash | 在法陣區施法 |
| connector 工具（`mcp__*`） | 拿出對應裝備 |
| compact | 坐下整理筆記 |
| 等待批准 | 放出信鴿，原地等待 |

- **同時做很多事**：
  - 同一回合多個工具呼叫 → **分身術**：分身同時前往各工作站，做完合回本體；同一工作站多件事只演一次並標 ×N；分身最多 4 個，其餘合併為「+N」【建議・未否決】。
  - subagent → **召喚使魔**，使魔自己行動，完成後飛回交付【決定：使用者認可】。
  - 背景長時間指令 → **營火／法陣**留在原地燃燒，指令結束後熄滅，結果飛回 NPC【決定：使用者認可】。
- **原則**：場上的狀態反映「現在」的真實狀況；動畫可以壓縮、合併、加速，但不能落後真實進度；完整細節看紀錄。
- **哪些 Bash 算「跑測試」【待驗證／建造者自定】**：可能讓每座地下城設定測試指令樣式。
- **點擊查看【決定】**：點艾拉、分身、使魔或營火，都跳出小視窗顯示它現在在做什麼（動作、實際指令、已執行時間、最後幾行輸出；使魔顯示被交付的任務與進度），並有「打開完整紀錄」連結。
- **玩家可做的事【建議・未否決】**：傳信（執行中插話，SDK 串流輸入）、召回（中斷）、回城（NPC 繼續）。

### 5.11 水晶球（統一查看）【決定】

- 類似 Claude Code 介面：左側列出所有 session（進行中置頂，依 NPC 分組），右側是完整對話，工具呼叫可展開、可看 diff、可回覆信鴿，底部有輸入框可傳信或續聊。
- 遊戲風格外觀，但排版以可讀性為主。
- 從城鎮的水晶球或快捷鍵打開【建議・未否決】。這也就是每個 NPC 的「冒險日誌」的總入口。

### 5.12 城鎮與操作

- 城鎮中心有佈告欄；周圍建築【建議・未否決】：酒館（招募）、法師塔（技能）、公會大廳（組隊，v2）、書庫（卷軸）、地下城入口。
- 移動：鍵盤（WASD／方向鍵），走到建築或 NPC 前按鍵互動【建議・未否決】。
- 視角（俯視或其他）、城鎮實際配置【建造者自定】，以 Greedy Cave 風格為準。

## 6. 資料模型方向

委託必須是**有明確狀態的資料**【決定】，為日後 Sprint 自動化預留。至少包含：來源（本地／Jira 票號）、標題與內容、難度星等、狀態（待接／冒險中／待驗收／已完成，另需「被退回」「放棄」的處理【建造者自定】）、指派對象（NPC，日後可為隊伍）、地下城、分支／worktree、session ID 列表、卷軸、結算紀錄。

NPC、技能、地下城、session 索引的完整欄位【建造者自定】。

## 7. 美術規範【決定】

- 全部自製 SVG，不用 emoji（草圖中的 emoji 都要換掉）。
- 一份美術規範：固定色盤（羊皮紙底、墨色、蠟封紅、幾個狀態色）、統一墨線粗細與線頭、同一個手繪抖動濾鏡。
- 角色由零件組合（頭、身體、裝備），換外觀＝換零件；走路用 Phaser 補間動畫擺動零件，不畫逐格動畫【建議・未否決】。
- 圖示（技能、裝備、建築、狀態）同一套規範。
- 素材集中在一份素材清單，未來可替換檔案而不改程式。
- **v1 美術精緻度【我的決定，可推翻】**：由實作者手寫 SVG，目標是「風格一致、簡潔」，約略等同草圖中城鎮 SVG 的程度（墨線＋抖動濾鏡＋羊皮紙），而不是精修插畫。先做規範與共用元件（線條、濾鏡、色盤、角色零件），再大量產出。精修留到 v1 之後。

## 8. v1 範圍總表

**v1 包含**：城鎮與移動；地下城地圖（登記本機專案）；酒館招募（職業模板、人設、模型／effort、背包式裝備與技能、駐地）；內建 NPC（公會櫃檯、酒館老闆、大法師、三位新手）；法師塔（抄寫、研究、編輯）；與 NPC 對話；佈告欄（分欄看板、本地委託、票號匯入 Jira）；派委託（worktree、auto mode、信鴿批准）；地下城觀戰（工作站、動作對照、分身、使魔、營火、點擊查看、傳信／召回／回城）；水晶球；驗收與結算；美術規範與所有 SVG 素材；本機安全設定；啟動時的 API key 檢查。

**v1 內的施作順序【決定】**：先打通真實工作，再補遊戲世界。

1. **里程碑一：真實工作的閉環**——派委託 → worktree → auto mode 執行 → 信鴿批准 → 驗收 → 開 PR／改 Jira／留言。佈告欄、水晶球、對話先用簡單但可用的畫面（照美術規範的色盤與字體，不求插畫）。完成後就能用來處理真實工作。
2. **之後**：城鎮與走動、酒館招募與背包、法師塔、地下城觀戰（工作站、分身、使魔、營火）、全部 SVG 素材。

過程中「能用但還不好看」的版本是可以接受的。

**v2**：隊伍（隊長帶隊，用 SDK subagent；整隊共用分支）；經驗值與等級（只在驗收通過後給；＝星等基本值 × 一次通過加成；被退回後通過給基本值；放棄給 0；用量／回合數／改動行數**不**算經驗值）；等級只換稱號與外觀；NPC 能力值（可靠度＝驗收通過率、速度＝平均完成時間、食量＝平均用量）；魔力泉（訂閱用量量表，前提是 SDK 拿得到）；成就與遠征（Sprint）；新手教學任務；從 GitHub／zip 匯入技能。

**更之後**：Sprint 整批匯入與自動規劃執行；隊員互相討論；Electron；系統通知。

## 9. 開工前要先做的技術實驗

1. `settingSources` 只含 `project`（不含 `user`）時，claude.ai connectors 是否仍載入。
2. 每個 NPC 只載入自己技能的作法。
3. 從 SDK 初始化訊息取得 connectors 清單。
4. 讓遊戲 session 存在遊戲自己的地方、不受 Claude Code 自動清理影響，同時仍能讀到 claude.ai 登入憑證。
5. `auto` permission mode 在 SDK 中的可用性與批准請求的實際觸發情形。

若實驗 1 或 2 不可行，需回頭與使用者討論替代方案。
